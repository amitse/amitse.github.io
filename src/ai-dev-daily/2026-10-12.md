# 🤖 AI Dev Daily — October 12, 2026

## Highlights

The meaningful follow-up to last week’s agent-runtime releases is not a new model leaderboard. It is the increasingly concrete machinery around delegation: a policy hook that fails closed, a smaller model assigned to high-volume tasks, an explicit choice of a local model, and a sandbox that can say it is too weak and refuse to run. That is where developer tooling becomes operational software rather than a persuasive chat interface.

---

## Agent controls are becoming product features

### Claude Code makes failure behavior explicit

[Claude Code v2.1.295](https://github.com/anthropics/claude-code/releases) added `onFailure: "block"` for command and HTTP hooks: if a hook cannot start, times out, or exits unexpectedly, the associated action can be blocked rather than allowed through. The same release added Program Status Protocol (OSC 7501), allowing compatible terminals to show whether Claude Code is working, waiting for the user, or finished. Those changes address two unglamorous but essential questions for unattended work: what is the agent doing, and what happens when the policy mechanism itself breaks?

The October 9 [v2.1.296 release](https://github.com/anthropics/claude-code/releases) continued that operational focus. It added a model constraint for workflow agents, an option for subagents to compact their context earlier, and `allow_large` for reading a whole text file when the context permits. These are not claims that delegation is solved; they are evidence that model selection, context limits, and recovery paths are being exposed as controls instead of hidden implementation details.

### Copilot ships model choice alongside execution boundaries

GitHub made [Claude Haiku 5.5 generally available in Copilot](https://github.blog/changelog/2026-10-07-claude-haiku-5-5-in-github-copilot/) on October 7. GitHub positions the lightweight model for fast, high-volume work such as subagents, quick edits, and terminal tasks, and says it is available to Copilot Pro, Pro+, Max, Business, and Enterprise users, subject to a gradual rollout. The important caveat is that GitHub’s claim about early coding-task performance is vendor testing, not an independently published benchmark.

That same day, GitHub made [local sandboxing generally available](https://github.blog/changelog/2026-10-07-local-sandboxing-for-github-copilot-now-generally-available/) for Copilot CLI, the Copilot app, and VS Code sessions using Agent Host. Its [weekly release summary](https://github.blog/changelog/2026-10-09-github-copilot-weekly-releases-october-5/) says the feature can limit agent access to files, networks, and credentials. In parallel, [Copilot CLI added local-model discovery](https://github.blog/changelog/2026-10-07-discover-local-models-in-github-copilot-cli/): starting with CLI version 1.0.94-0, `/model` can discover supported models from a running local Ollama instance. Model selection and tool isolation are separate decisions, and shipping them together is the right product shape.

### The editor is turning sessions into durable work

[VS Code 1.141](https://code.visualstudio.com/updates/v1_141), released October 7, makes that same shift visible in the editor. Its release highlights include cleanup for inactive agent-session worktrees, cross-platform terminal sandboxing, a grid for monitoring sessions, and continuation of external Copilot and Codex conversations. The Copilot harness runs in a dedicated Agent Host process, and VS Code says the same agent session can be connected to from multiple windows.

The implication is straightforward: an agent session is no longer being treated as disposable chat history. It has storage to reclaim, processes to observe, boundaries to set, and a lifecycle to manage. That is more complex than a single prompt box, but it is also closer to how development work actually behaves once tasks run for long enough to leave state behind.

## A useful standard for sandbox claims

[Plimsoll](https://github.com/plimsollmark/plimsoll) offers a compact way to evaluate the language around agent execution. Its README says each result reports an isolation tier—`process`, `container`, `kernel`, or `vm`—and a request can require a minimum tier; if the available sandbox is weaker, it does not run. The project explicitly distinguishes the evidence it collects from cryptographic attestation.

That distinction is worth carrying into every agent-runtime announcement. “Sandboxed” is not a sufficient security property by itself. A useful system should state the boundary it actually achieved, let a caller set a minimum acceptable boundary, and fail safely when it cannot meet that requirement. The promise is not perfect safety; it is a property that can be inspected and enforced.

---

## What to watch next week

Watch whether these controls remain coherent as vendors add more handoffs, subagents, and model choices. The feature race is no longer only about which assistant can write code fastest. It is about whether teams can see what a delegated task is doing, constrain what it can touch, choose an appropriate model for it, and recover when something fails.
