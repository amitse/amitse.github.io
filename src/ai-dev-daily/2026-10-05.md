# 🤖 AI Dev Daily — October 5, 2026

The useful question in AI-assisted development is shifting from “which model can produce a patch?” to “what process contains the patch after it exists?” This edition’s new material is almost entirely about that second question. VS Code is adding an explicit host for persistent, multi-folder agent sessions; GitHub is making Copilot review callable from a team’s own systems; and Claude Code’s latest release is largely a tour of the edge cases that permission and plugin systems must get right. None of this makes agents infallible. It makes their operation more legible—and that is the prerequisite for trusting them with larger work.

## 🚀 Releases & Changelogs

[Visual Studio Code 1.140](https://code.visualstudio.com/updates/v1_140), released September 30, expands the editor’s agent-workflow surface rather than simply adding another chat feature. The release introduces the Copilot harness, which runs in a dedicated Agent Host Protocol process so the same agent session can be connected from multiple VS Code windows. It also adds experimental multi-folder sessions, experimental delegation to connected remote agent hosts, and shared worktree folders intended to avoid repeated dependency installation and duplicated ignored artifacts.

The most consequential experiment is HydraFusion, a research preview in which multiple models can draft, critique, and revise coding tasks without the user coordinating each handoff. The preview label matters. Multi-agent systems create a coordination problem alongside the coding problem, and VS Code is exposing that coordination as a product surface rather than pretending it is invisible. The worktree reuse feature is an especially practical signal: once several agents operate over related checkouts, disk state, dependencies, and cache reuse become part of the developer experience.

[Claude Code v2.1.289](https://github.com/anthropics/claude-code/releases/tag/v2.1.289), published October 3, is principally a hardening release. It fixes a deny-or-ask rule that could fail to carry over a user-installed mod’s approval on managed machines; fixes `Read` deny rules bypassed via certain IDE paths through a symlink; and fixes cases in which Bash deny or ask rules missed a command following an environment-variable prefix under sandbox auto-allow. It also prevents a user-installed plugin from rewriting the descriptions of an organization-managed MCP server’s sign-in tools.

These are not glamorous release-note bullets, but they are the ones teams should care about. Plugins, MCP servers, shell rules, and sandboxing are where an agent becomes an operational system with real authority. A feature that appears to enforce a policy but fails on a compound command, a symlink, or a plugin-mediated prompt is worse than a visibly absent control: it creates false confidence. The immediate lesson is prosaic—update—but the strategic one is bigger. Treat the extension and policy layer as production infrastructure, with its own patch cadence and review.

## 🛠️ Tool Updates

### GitHub Copilot / Copilot CLI / Coding Agent

GitHub’s October 2 [Copilot code-review update](https://github.blog/changelog/2026-10-02-copilot-code-review-api-support-and-new-default-effort-level) adds REST and GraphQL API support for requesting a Copilot review and setting the review-effort level per request. GitHub also says Balanced became the default review-effort setting on September 28 for new and existing repositories and organizations using Copilot code review, while explicit Lite selections remain respected.

The API matters more than the selector. A review agent becomes part of an engineering system only when it can be invoked from the places where engineering systems already make decisions: CI, internal release tooling, or repository automation. That should not mean blindly blocking merges on an agent’s finding. It does mean a team can define when a review is requested, which effort level is appropriate, and how the result reaches a human reviewer instead of relying on a remembered click in a web interface.

### VS Code (stable + insiders)

VS Code 1.140’s harness is an attempt to give agent sessions a durable home. A normal chat interaction is easy to start and hard to reconstruct; a dedicated host process and multi-folder session are more compatible with work that crosses repositories, machines, and worktrees. The appropriate posture is supervised adoption: use the experimental features to learn where delegation saves time, but retain normal code review and environment boundaries while the host and remote-delegation model mature.

### Claude Code CLI

The v2.1.289 fixes underline why extension mechanisms cannot be evaluated only by their happy paths. If an organization permits mods or MCP servers, it needs to know that denial rules still work when a command’s syntax gets strange and that a local plugin cannot misleadingly rewrite an organization-managed authentication prompt. Those are integrity properties, not interface polish.

## 💡 How People Are Using It

The common use case is not a fully autonomous engineer. It is a developer or team placing agent work inside existing operating procedures: one system requests review through an API, another preserves session identity across windows and folders, and another has to make permission decisions hold across plugins, shell syntax, and IDE integration. That is a more mature pattern than chasing ever-longer unattended runs. The agent supplies acceleration; code review, environment policy, and explicit checkpoints continue to supply accountability.

## 🔥 Discourse & Drama

The real tension is between convenient delegation and enforceable boundaries. API-triggered review makes it easy to scale an agent’s presence across a team. Multi-host sessions make it easier to distribute tasks. Plugins and MCP make it easier to connect the agent to the surrounding world. Each capability is useful precisely because it broadens the system’s reach—and therefore increases the cost of a fuzzy permission model. The winning tools will not be those that hide this tension behind an autonomy demo. They will be the ones that make authority, session ownership, and overrides inspectable.

## 📊 TL;DR

VS Code 1.140 is a substantial step toward treating agent sessions as hosted, multi-workspace processes rather than disposable chats, but its most ambitious pieces remain experimental or research previews. GitHub’s new REST and GraphQL support lets teams place Copilot code review inside their own automation and choose effort per request. Claude Code v2.1.289 is a security- and reliability-relevant update for users of mods, managed MCP servers, IDE integration, and shell permission rules. Across all three, the priority is operational control: make the agent’s work visible, scoped, and reviewable before widening what it is allowed to do.
