# 🤖 AI Dev Daily — 29 July 2026

_This week’s dominant story is not a new autocomplete trick or another benchmark claim. It is the hardening of the machinery around autonomous coding: agents are being given security jobs, tool protocols are becoming stateless infrastructure, and model choice is turning into a governed operational decision rather than a personal preference. That is progress—but it also makes the failure modes more consequential. The useful question is no longer “can the agent write code?” It is whether an organization can let it act, inspect what it did, and stop it when its confidence exceeds its competence._

## 🚀 Releases & Changelogs

The consequential release this week is the [MCP 2026-07-28 specification](https://blog.modelcontextprotocol.io/posts/2026-07-28/), which moves the protocol core from bidirectional, session-oriented transport to stateless request/response. That sounds like plumbing, and it is—but plumbing determines whether an agent system remains a demo or becomes deployable. Each request is self-describing and can land on any server instance behind a round-robin load balancer rather than being tied to a protocol session. The new version also sends method and tool names in `Mcp-Method` and `Mcp-Name` headers, allowing gateways, WAFs, and rate limiters to apply rules without parsing JSON request bodies.

The release makes an unusually direct case for the ordinary properties of web infrastructure. Server-to-client interactions such as sampling and elicitation move to Multi Round-Trip Requests rather than held-open bidirectional streams. List responses gain cache hints and deterministic ordering. Roots, Sampling, Logging, and the legacy HTTP+SSE transport are deprecated with at least a 12-month window. MCP reports that its TypeScript and Python SDKs have each crossed one billion cumulative downloads, while its Tier 1 SDKs are approaching half a billion downloads per month. Those are ecosystem measures, not proof of production adoption, but they explain why a transport rewrite matters more than another agent wrapper.

GitHub’s model picker also grew more crowded. On July 28, [Grok 4.5 became available in GitHub Copilot](https://github.blog/changelog/2026-07-28-grok-4-5-is-now-available-in-github-copilot/), with a context window of up to 500,000 tokens, image input, and low, medium, and high reasoning effort. GitHub says its internal terminal-based coding tests found the model particularly effective when dispatching tools in parallel and taking direct action. It is rolling out to Pro, Pro+, Max, Business, and Enterprise plans under provider-list-price, usage-based billing; Business and Enterprise administrators must enable the policy, which is off by default.

That followed [Claude Opus 5’s July 24 arrival in Copilot](https://github.blog/changelog/2026-07-24-claude-opus-5-is-now-available-in-github-copilot/). GitHub positions it for long-running, multi-step coding work and says early testing found it effective at targeted changes, validation, and coordinating multiple tools. It is likewise billed at provider API list price under usage-based billing, and its enhanced high-harm cyber safeguards can block some security-related requests. The old instruction to “pick the smartest model” is giving way to a more realistic decision: choose a capability, cost, and policy profile.

## 💡 How People Are Using It

The clearest new workflow is [Codex Security](https://github.com/openai/codex-security), OpenAI’s open-source CLI and TypeScript SDK for finding, validating, and fixing vulnerabilities. Its README says it can scan repositories, review changes, track findings over time, and run security checks in CI. The quick-start path is intentionally ordinary: install `@openai/codex-security`, authenticate, and run `codex-security scan .`; it requires Node.js 22 or later, Python 3.10 or later, and Codex Security access. CI can use `OPENAI_API_KEY`.

At fact-check time, the [Hacker News front page](https://news.ycombinator.com/) listed Codex Security at 356 points and 106 comments. The interest is warranted, but it is not a security validation. The important shift is workflow placement. This is not an assistant waiting in a chat pane for someone to paste a suspicious function; it is packaged as a repeatable scanner that can enter review and CI. The practical test for coding agents is increasingly whether they can be a continuously available adversarial reader of patches, not merely whether they can write the first patch.

That is why MCP’s redesign matters here. Security agents gain leverage when they can reach repositories, ticketing systems, scanners, build logs, and deployment metadata. Each connection also multiplies the importance of authorization, routing, and auditability. A stateless request whose tool name is visible to a gateway is not only easier to scale; it is easier to police. Agentic security without operational discipline is high-speed permission sprawl.

## 🔥 Discourse & Drama

Anthropic supplied the week’s sharpest illustration of the promise and risk of capable coding/research agents with its July 28 report, [“Discovering cryptographic weaknesses with Claude”](https://www.anthropic.com/research/discovering-cryptographic-weaknesses). At fact-check time, the HN front page listed the story at 183 points and 129 comments. The report claims a model helped discover flaws in cryptographic algorithms themselves, rather than only implementation mistakes.

The headline result needs precise boundaries. Anthropic says Claude Mythos Preview improved an attack on HAWK, a post-quantum digital-signature candidate, in about 60 hours, cutting its effective key strength in half. It reports that the expected cost of a full key-recovery attack against small HAWK-256 fell from \(2^{64}\) to a demonstrated \(2^{38}\). It also reports a 200–800× improvement over the best previous attacks on a reduced-round AES variant. Each result cost roughly $100,000 in API spending to develop. This is not “AES is broken”: HAWK is a candidate and not deployed, while the AES result concerns a reduced version rather than the full cipher. As Anthropic puts it, “neither of these results has a practical impact on today’s computer systems.”

The methodological claim is just as important: “Mythos Preview achieved these results mostly autonomously and mostly without human intervention.” For the HAWK work, Anthropic says its human operator had a theoretical-computer-science background but no lattice-cryptography expertise; agents read literature, reasoned, ran experiments, and built a verification pipeline. One worker rejected the key idea while another pursued it, before the pair converged. That is a specific vision of useful multi-agent work: not magic and not zero-human, but a parallel research operation with tools and verification.

The tension is not whether AI can help defenders. It can. The same systems that lower the cost of finding cryptographic weaknesses also lower the cost of searching for them, while deployment and governance lag capability. Anthropic says it followed responsible-disclosure procedures and coordinated its HAWK finding with the authors and the public NIST mailing list. That is necessary, but it is not a complete governance model. As models combine literature search, code, mathematics, and autonomous experiments, access boundaries, logging, review, and scoped permissions become as important as raw capability.

## 📊 TL;DR

MCP’s stateless redesign is the week’s most important release because it makes agent-tool infrastructure more routable, cacheable, and governable. GitHub’s additions of Grok 4.5 and Claude Opus 5 turn the Copilot model picker into a real cost-and-policy surface. Codex Security shows the near-term destination for coding agents: repeatable scanning and validation inside CI, not just chat-assisted edits. Anthropic’s cryptography report shows a more consequential destination—multi-agent systems doing research-grade exploratory work for about $100,000 per major result. Capability is arriving faster than operational discipline, so the tooling that constrains agents is now as important as the tooling that empowers them.
