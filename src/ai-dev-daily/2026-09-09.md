# 🤖 AI Dev Daily — September 9, 2026

## Highlights

The important AI-development story this week is not a new model. It is the unglamorous work of making agents survivable in real developer environments: plugin trees that change while a session is running, tool output that must not grow without bound, interrupted subprocesses, and network configurations that cannot be broken by a quiet semantic change. Claude Code’s two September 8 releases are a compact case study in that work.

The other half of the story is the human handoff. A popular skill for concise coding-assistant output sparked a Hacker News discussion that was, at heart, a complaint about operational usability: a model can produce fluent prose and still make the user spend too long locating the action, result, or remaining decision. These are connected problems. More capable agents need both dependable boundaries and reports a developer can act on.

## Claude Code: persistence needs operational limits

### Version 2.1.265 adds dynamic plugin discovery and bounds saved output

[Claude Code 2.1.265](https://github.com/anthropics/claude-code/releases/tag/v2.1.265), released September 8 at 20:37, added support for using `--plugin-dir` with a folder of plugins: child folders containing manifests are loaded, and additions or removals are picked up while the session is running. That is a useful packaging improvement for teams, but it also expands the surface that needs policy and containment controls.

The release makes that tension visible. It caps tool results saved to disk at 1 GB and tells the user when a saved file was truncated in the in-conversation preview. It also fixes prompt-cache reuse failures involving resumed subagents, preserves and marks an interrupted tool call when the prior process dies, and repairs a macOS/Linux symlink-containment bypass caused by a plugin path containing a backslash. These are not cosmetic details: agent state, artifacts, and local paths are now part of the reliability and security contract.

### Version 2.1.266 reverses a gateway authentication regression

Just over three hours later, [Claude Code 2.1.266](https://github.com/anthropics/claude-code/releases/tag/v2.1.266) repaired a regression from 2.1.265 affecting LLM-gateway and proxy setups. Anthropic says the undocumented `CLAUDE_CODE_USE_GATEWAY` environment variable had begun forcing Cloud-gateway sign-in when set alone; configurations using an API key, `apiKeyHelper`, or custom authorization headers consequently failed requests with “Not signed in to the Cloud gateway.” The correction restores the prior behavior: the variable alone is ignored and no configuration change is required.

Rapid remediation is good, but the episode is a reminder that undocumented switches are not harmless once coding agents reach enterprise networks. Gateway and proxy environments are where authentication, audit, routing, and internal model endpoints collide. At that boundary, stable documented configuration matters more than clever defaults.

## Community: concise output is an interface requirement

### A skill that puts the action first

The repository [I-have-ADHD](https://github.com/ayghri/i-have-adhd) describes itself as a skill for coding assistants that stops them from “burying the answer”: “Action first. Steps numbered. No ‘Hope this helps!’” Its published guidance also calls for specific time estimates, matter-of-fact errors, no preamble or recap, and lists capped at five items. The framing is accessibility-oriented, but the design proposal is broader: output format is part of an agent’s interface, not post-processing decoration.

Its [Hacker News discussion](https://news.ycombinator.com/item?id=49610631) had **326 points and 256 comments** when fetched for this edition. The thread included a pointed complaint about verbose model prose: “unnecessary participle phrases, not-this-but-thats, burying the lede, and other nonsense.” The reaction is useful signal, not a popularity contest. Developers are asking for an assistant that makes the next action, the concrete result, and the unresolved question immediately visible.

The consequence is more substantive than a style preference. As agents take on longer delegated tasks, their status report becomes the handoff between autonomous work and human judgment. Claude Code’s fixes for interrupted calls and background state aim to preserve an accurate record of what happened. A concise output policy aims to make that record legible. The product category needs both: faithful execution history and an interface that does not force a developer to search a monologue for the conclusion.

## Local experimentation: storage is part of the model architecture

### Deltafin streams a 2.8T MoE model from SSDs

[ARGODRIVE Deltafin](https://github.com/argonautlabsai/deltafin) reports a September 8 benchmark of the 2.8-trillion-parameter Kimi K3 mixture-of-experts model, with 1.45 TB of expert weights streamed from four SSDs on an M5 Max MacBook Pro with 128 GB of memory. Its recorded steady decode rates were **1.0015 tokens/second** over 512 generated tokens and **1.1252 tokens/second** over 128 tokens.

The project is equally clear about the limitation: a 512-token prompt took roughly **6.3 minutes to first token** in the reported configuration. It attributes the delay to prefill re-reading each layer’s experts eight times and says a fix is planned rather than implemented. Its drive-scaling results—about 52% of four-drive speed with one drive, 73% with two, and 90% with three—underscore the systems lesson: the slowest of 16 reads per layer, rather than aggregate bandwidth, sets the pace.

This is not an interactive coding setup today. It is, however, a useful demonstration that some local-model questions are becoming storage-scheduling questions rather than simply accelerator-capacity questions. For agent builders, “can it run?” is the wrong finish line; the relevant question is whether its latency profile works inside an edit-test-debug loop.

## What to watch next

Watch whether coding-agent vendors make network, plugin, and saved-artifact behavior explicit enough for teams to operate them confidently. The next meaningful feature is unlikely to be a prettier chat pane. It will be a control that makes long-running work more inspectable, recoverable, and safe.

Also watch for product-level concise-output controls. A skill can impose useful discipline today, but a durable agent interface should let users choose a dependable status format without relying on a large prompt layer. The tools that combine that clarity with truthful failure reporting will earn more trust than the ones that merely sound the most helpful.
