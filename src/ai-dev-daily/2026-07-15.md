## 🚀 Releases & Changelogs

The most headline-grabbing model news this week came from PrismML, a company that has quietly been building one of the more technically audacious positions in local inference. On July 14, they announced [Bonsai 27B](https://prismml.com/news/bonsai-27b) — 424 points, 160 comments on HN — billing it as "the first 27B-class model to run on a phone." That claim holds up on inspection. A standard 27B model occupies around 54 GB at 16-bit precision, and even a 4-bit quantization lands at 18 GB, which is too large for any current mobile device. Bonsai gets there with genuine ternary-weight compression: the 1-bit variant uses binary {−1, +1} weights at 1.125 effective bits per weight, landing at 3.9 GB — within the memory budget of an iPhone 17 Pro. The quality-oriented ternary variant (5.9 GB, using {−1, 0, +1} weights at 1.71 bits per weight) runs on an everyday laptop. Across a 15-benchmark suite, ternary Bonsai 27B retains 95% of the full-precision baseline quality, and the 1-bit variant retains 90%. Both are multimodal, carry a 262K-token context, and support speculative decoding. Everything is Apache 2.0. This is the kind of milestone that looked theoretical 18 months ago.

PrismML's arch isn't alone in the "27B on constrained hardware" space — Bonsai competes directly with llama.cpp-optimized GGUF models — but the compression technique here is meaningfully different. Ternary weights run end-to-end including embeddings, attention, and the LM head. No escape hatches. That's the claim worth watching.

On the model availability front for hosted tools: GitHub Copilot [added OpenAI's GPT-5.6 family](https://github.blog/changelog/2026-07-09-openais-gpt-5-6-sol-terra-and-luna-are-now-available-in-github-copilot/) on July 9. The family comes in three variants: Sol (highest reasoning ceiling, for large-codebase work and long-running agents), Terra (balanced default, all-round interactive and agentic coding), and Luna (cost-efficient, best for smaller and faster tasks). Sol is available on Copilot Pro+, Max, Business, and Enterprise; Terra and Luna extend down to Pro. Kimi K2.7 also reached Copilot Business and Enterprise on July 7, after first landing in the general Copilot picker on July 1. The model picker is getting crowded.

### Claude Code CLI

[Claude Code](https://github.com/anthropics/claude-code/releases) shipped a remarkable volume this week. By July 14, it had reached v2.1.210 with three releases that day alone (v2.1.208 through v2.1.210). The substantive additions are concentrated in 208 and 210. Version 2.1.208 shipped a screen reader mode (`claude --ax-screen-reader` or `CLAUDE_AX_SCREEN_READER=1`) for opt-in plain-text rendering, a `vimInsertModeRemaps` setting for two-key insert sequences, and `CLAUDE_CODE_PROCESS_WRAPPER` for enterprise environments requiring a corporate launcher wrapper. Version 2.1.210 added a live elapsed-time counter on collapsed tool summary lines — small UX, real frustration solved — and added startup warnings for `Write(path)`, `NotebookEdit(path)`, and `Glob(path)` permission rules, pushing users toward safer `Edit(path)` and `Read(path)` alternatives. A critical worktree isolation fix also landed: subagents were previously able to run git-mutating commands against the main repo checkout instead of their isolated worktrees. That's not a minor bug. Version 2.1.207 brought auto mode to Bedrock, Vertex AI, and Foundry without needing the opt-in flag, and fixed a terminal freeze under long streaming responses. Version 2.1.203 added login expiry warnings so background sessions don't silently break mid-task.

The pattern across all these releases is a team aggressively paying down operational debt on background agents — the feature that makes Claude Code useful for long-running autonomous work but that has had a rocky production history.

## 🔥 Discourse & Drama

The week's hardest news is the Cursor 0day. [Mindgard disclosed](https://mindgard.ai/blog/cursor-0day-when-full-disclosure-becomes-the-only-protection-left) (248 points, 106 comments) a vulnerability they first reported to Cursor on December 15, 2025 — over seven months ago. The bug is not subtle: when a developer opens a repository in Cursor on Windows that contains a malicious `git.exe` at the project root, Cursor executes it automatically, repeatedly, on a cadence, with no user interaction, no prompts, no approval dialogs, no warnings. Arbitrary code execution via opening a repo. Mindgard tried every available channel over seven months, through 197+ new Cursor versions. No response. Full disclosure became the only lever left.

The numbers make the stakes concrete: 7 million+ active Cursor users, 1 million+ daily, 1 million+ paying, 50,000+ companies, a reported $60 billion market valuation. For a tool positioned as enterprise-ready, the non-response to a responsible disclosure over seven months is a governance failure, not just a security one. The structural tension is this: Cursor's entire value proposition is that you trust it with your codebase. That trust is not compatible with an unpatched RCE that fires when you open a repo. The community's mitigation advice is brutal in its minimalism — until this is patched, open untrusted repositories only in an isolated VM or Windows Sandbox.

The [Thoughtworks piece](https://www.thoughtworks.com/insights/blog/open-source/zero-cost-fallacy-open-source-agentic-era) on "The zero-cost fallacy: open source software in the agentic era" (21 points, 380 comments — the largest comment-to-point ratio on the front page this week, by far) opened a slower-burning argument: AI systems are trained on open-source code, generate open-source-style code, and are used to generate PRs to open-source projects — all while the actual maintainers doing the review and maintenance work see none of the value capture. The question isn't whether this is happening; it's whether the incentive structure can survive it. The 380-comment thread suggests the community has strong feelings and no consensus. The piece was published July 9; the comment volume reflects a genuine unresolved tension.
