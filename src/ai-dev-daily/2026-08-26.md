# 🤖 AI Dev Daily — August 26, 2026

This is a deliberately narrower edition. What is actually new is subtler: GitHub is turning customization into a product surface, while Anthropic is continuing to harden the tiny permission and transcript failures that determine whether an agent is safe to leave alone. ## 🚀 Releases & Changelogs

GitHub’s most consequential fresh release is the [Copilot app’s new Customize tab](https://github.blog/changelog/2026-08-25-github-copilot-app-customize-tab-is-generally-available), generally available August 25. It brings MCP servers, plugins, skills, and canvases together in one place, with featured customizations, categories, and trending MCP servers. That could sound like a navigation redesign. It is better understood as GitHub admitting that a generic agent is not the unit of adoption anymore; the useful unit is an agent embedded in a team’s tools, knowledge, and operating habits.

GitHub’s own wording is unusually candid about the aim: Copilot is “more useful when it works with the tools, knowledge, and workflows your team already relies on.” This is true, but it exposes the tension vendors have spent a year trying to postpone. The easier GitHub makes it to discover and install connections, the more important governance becomes. An MCP server is not a decorative extension—it can expose source code, issue trackers, deployment systems, or internal services. The industry has largely solved the *format* problem with plugins and MCP; discovery is the next frontier, and discovery without curatorial and administrative controls is how a useful marketplace becomes an attack surface.

Claude Code’s [v2.1.246 release](https://github.com/anthropics/claude-code/releases/tag/v2.1.246), published August 25, is smaller but more revealing. It adds an Auto mode tab to `/permissions` for viewing and editing classifier rules, and warns users about Bash allow rules with a wildcard before the subcommand because those patterns also match options inserted before that subcommand. The release note’s concrete example—`Bash(git * main)`—is exactly the kind of configuration that looks narrowly scoped until an agent finds a surprising interpretation of it. This is the adult work of agent tooling: not more demos of autonomy, but refusing to pretend that permissions are intuitive just because they fit in a config file.

The same release fixes a severe transcript slowdown when a diff contains a very long single line, rendering those lines truncated with a marker. It also fixes fullscreen rendering and several background-session failures. That is not glamorous. It is, however, the difference between a transcript being evidence and it being a frozen terminal window precisely when someone needs to inspect what an agent changed.

## 🛠️ Tool Updates

### GitHub Copilot / Copilot CLI / Coding Agent

The Customize tab is the only newly verified Copilot product change since the last edition. Its decision to put MCP servers, plugins, skills, and canvases beside each other matters because it treats them as complementary layers rather than competing brands of extensibility. A skill encodes procedure; an MCP server provides access; a canvas keeps context and actions visible. The practical result should be a shorter path from “we use this internal system” to “Copilot can work with it.”

But GitHub should resist confusing discoverability with trust. “Featured” is a powerful default, especially for developers who do not know which integration they need. The product will be judged less by how many integrations it can surface than by whether teams can understand what an integration grants, who approved it, and what data leaves the repository boundary. The new tab is a promising front door. It also makes the policy layer behind the door non-negotiable.

### Claude Code CLI

Claude Code’s late-week cadence is focused on legibility. The permission-rule interface gives Auto mode a visible control surface, rather than leaving its behavior as an opaque convenience feature. And the startup warning for broad Bash allow rules makes a structural risk explicit before an agent can exploit a human’s fuzzy mental model of shell syntax.

That is a better philosophy than presenting safety as a binary “approve” button. Agent permissions are a language, and languages have edge cases. A tool that tells users when a permissive-looking rule is actually broad is doing more for safe autonomy than another round of benchmark claims. The transcript fixes carry the same implication: an autonomous session that cannot be reviewed quickly is not operationally autonomous; it is simply unsupervised.

## 💡 How People Are Using It

The most telling community signal was not a splashy new autonomous-coding platform. Today’s [Show HN](https://news.ycombinator.com/show) page included **MulmoTerminal**, a local, tmux-backed browser terminal grid for running multiple Claude Code and Codex sessions and showing which agent needs attention. It had **4 points and 5 comments** when checked. Those are modest numbers, not evidence of a breakout product, but the use case is worth watching. The project’s [repository](https://github.com/receptron/mulmoterminal) describes it as local, tmux-backed, and MIT licensed.

The premise is management, not magic: developers are beginning to need an inbox for their agents. Once a person runs multiple sessions, the scarce resource is no longer merely tokens or model intelligence—it is intervention timing. Which session is blocked? Which one is waiting for a decision? Which is about to make a risky change? The fact that someone built a monitoring surface for parallel agent terminals is a useful corrective to the marketing image of one all-capable assistant. Real use is increasingly supervisory work over a fleet of partial, fallible processes.

That connects directly to Claude Code’s transcript and permission work. A grid can show that five agents are active; it cannot establish that their privileges are well-scoped or that their output remains inspectable. The emerging agent workstation needs both: operational visibility across sessions and trustworthy evidence within each session.

## 🔥 Discourse & Drama

The argument worth having is not whether MCP, skills, or plugins are “the” extension mechanism. GitHub’s Customize release treats the question as settled enough to put all three into a common storefront. The unresolved issue is who gets to define what is safe enough to be easy.

Developers want frictionless access to the systems where the real work happens. Security and platform teams need a legible account of tools, credentials, network reach, and data flow. Vendors will be tempted to frame restrictions as an obstacle to productivity; that is backwards. Without restrictions that can be inspected and administered, ambitious organizations will simply decline to grant agents meaningful access. Governance is not the thing that follows adoption. It is the condition that makes broad adoption possible.

Anthropic’s Bash-rule warning is the small-scale version of the same problem. Permission models fail when they are technically precise but cognitively misleading. GitHub’s integration directory may create a similarly dangerous gap if its discovery experience is more polished than its explanation of capabilities and risk. The winners will be the products that make powerful connections understandable before they make them one-click installable.

## 📊 TL;DR

GitHub’s Customize tab is an important move because it makes the agent ecosystem—MCP, plugins, skills, and canvases—a first-class Copilot product surface rather than a collection of specialist configuration files. That is useful only if governance remains as visible as discovery. Claude Code v2.1.246 makes the right kind of incremental progress: permission-rule clarity, warnings for deceptively broad Bash rules, and repairs to the transcript experience needed for review. The community’s small but pointed MulmoTerminal experiment shows where real usage is heading: developers managing multiple agents, not conversing with one magical assistant. The competitive edge is increasingly the control plane around the model.
