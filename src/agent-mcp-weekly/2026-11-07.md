# 🔌 AI Agent & MCP Weekly — Week of 2 November 2026

## Highlights

The dominant signal this week is that the agent stack is finally admitting that a conversation is not a security boundary and a model response is not a transaction. The useful releases are not adding another planner or a bigger crew: they are adding identity to interruptions, lifecycle events to streams, and session semantics that can survive actual use.

## MCP protocol and servers

Nothing notable shipped in the MCP specification itself this week. The [MCP releases page](https://github.com/modelcontextprotocol/modelcontextprotocol/releases) still lists the stable `2026-07-28` revision as the latest protocol release, so this is not a week for pretending that protocol churn is progress.

But an MCP-adjacent security report deserves attention because it identifies a boundary that protocol adopters can easily get wrong. A November 5 post on the [OpenAI Developer Community](https://community.openai.com/t/security-follow-up-tool-call-silently-routed-to-a-different-connector/1413053) describes a multi-step flow in which a user confirmed an action through one connector, then the follow-up tool call was silently routed through another connector pointing at the same MCP server. The server rejected the one-time code because it was bound to the first connector’s OAuth client; that rejection is reassuring. The routing behavior is not.

The report’s most important sentence is worth preserving verbatim: **“The boundary is the connector with its own OAuth client, not the URL.”** That is the correct architectural framing. An MCP endpoint is an address, not an identity. Treating “same server URL” as equivalence collapses separate OAuth grants, tenants, app registrations, and user expectations into one ambient-authority blob. An agent runtime needs to carry connector identity through a tool workflow just as deliberately as it carries an idempotency key through a payment workflow.

The report appeared on [Hacker News](https://news.ycombinator.com/item?id=50399569) at **76 points and 33 comments** when checked. The comments spend considerable time on the bug-bounty identity requirement, but the enduring technical issue is authorization continuity. Tool choice is not merely model routing; it is a choice of principal. A future MCP client that lets the model freely “helpfully” switch connectors mid-flow is not composable—it is confused about who is acting.

## Agent frameworks

[LangGraph 1.2.20](https://github.com/langchain-ai/langgraph/releases/tag/1.2.20), released November 5, makes a small but unusually consequential correction: every `interrupt()` in a task now gets its own ID, and the release adds a strict-resume mode that refuses stale interrupt answers. The [SDK 0.4.14 release](https://github.com/langchain-ai/langgraph/releases/tag/sdk%3D%3D0.4.14) carries that discipline out to `runs.create`, streaming, and waiting; it also adds tools and lifecycle events to `StreamMode`.

This is a mature design decision. Early agent frameworks treated human approval as an ornament on a chat turn: pause, show a question, resume. In production, a pause is state. There may be multiple outstanding questions, a cancellation, a reconnecting client, a retry, or an answer that arrived after the task already progressed. If an approval answer does not name the specific interrupt it resolves, the runtime is relying on timing and hope. “Strict resume” is therefore not a UX preference; it is a refusal to perform an irreversible effect against ambiguous state.

There is a broader pattern here. The agent application is becoming less like a prompt loop and more like a workflow engine whose transitions happen to be proposed by a model. Lifecycle data in streams matters for the same reason: operators need to see whether a run is planning, blocked on a tool, waiting for a human, or actually complete. The model’s final prose is a bad substitute for runtime truth.

[CrewAI 1.15.36](https://github.com/crewAIInc/crewAI/releases/tag/1.15.36), released November 6, takes a different route toward the same destination. It adds experimental conversational Agent sessions and, more concretely, fixes async execution of synchronous tools in the caller’s context. It also records the error class when `crewai run` cannot load a project and stops a JSON crew run cleanly when its API key is missing.

None of that is glamorous, which is exactly why it matters. “Agent sessions” without predictable tool execution become a long-lived source of nondeterminism. And a CLI that records *which class of error occurred*, rather than merely failing somewhere in a transcript, gives teams the beginning of a failure taxonomy. These are the edges where a demo becomes operable software.

## Agentic patterns and architectures

The week’s arc is **continuity of authority and continuity of state**. The connector report says that an approval code must stay attached to the OAuth client that obtained it. LangGraph says an interrupt answer must stay attached to the exact interruption that requested it. CrewAI says tool execution must preserve the caller’s context, and startup failure must retain its cause.

These look like unrelated release-note items only if one thinks of agents as chats. They are all assertions that context has structure. “The model has the conversation history” is not an adequate representation of authorization, workflow state, or causality. Those must be first-class runtime objects with identifiers, ownership, expiry rules, and logs.

Builders should be especially wary of the superficially convenient design in which a tool result is simply injected back into the conversation and the model decides what to do next. That works until a confirmation token is replayed, a reconnect causes an old approval to arrive late, or two integrations share a server URL while representing different clients. The right default is more boring: bind sensitive artifacts to a run ID, interrupt ID, connector/client ID, user ID, intended action, and expiration; reject any mismatch before the model gets another turn.

## Notable projects and demos

Simon Willison’s [recent site updates](https://simonwillison.net/) highlighted `datasette-agent` 0.5a0 on November 3 and an accompanying `datasette-apps` update on November 4. The notable idea is not “chat beside a database,” which is becoming common. It is that the agent sits beside the page and can create or modify a database-backed application while permissions are checked at the application boundary.

The update describes tools that manage which stored queries an app may call, and says that granting a write query requires explicit user approval. That is a more credible pattern than allowing an agent broad database access and hoping its instructions remain cautious. The capability is being narrowed to the query surface, then approval is required at the point where a read-oriented application becomes a writer.

This is an instructive contrast with the connector issue: both are really about refusing to infer authority from nearby context. A user viewing a database is not thereby authorizing any write. Two tools sharing a server endpoint are not thereby one application. Agent infrastructure becomes safer when it stops treating adjacency as delegation.

## What to try next week

Implement a **capability envelope** for every approval-gated tool call this week. When an agent asks a user to approve an external action, persist an immutable record containing the run ID, tool-call ID, connector/OAuth client ID, user ID, normalized action payload, expiration, and a single-use nonce. On resume, validate every field server-side; do not let the model reconstruct the intended action from chat history.

Then test three failure cases: submit the same approval twice, answer a previous interrupt after a newer one exists, and route the approval through a different configured connector with the same backend URL. If any case succeeds, the system is relying on conversational resemblance instead of identity. LangGraph’s new strict-resume direction and this week’s connector report both point to the same lesson: exactness is a feature.

## TL;DR

MCP itself was quiet, but a newly reported connector-routing issue made the protocol ecosystem’s most important unsolved problem visible: endpoint equality is not authorization equality. The report’s recommendation—that connector/OAuth-client identity, not server URL, defines the boundary—is the correct design rule for multi-step tool workflows. LangGraph 1.2.20 and SDK 0.4.14 independently reinforce the state side of that rule with uniquely identified interrupts, strict resume, and richer lifecycle streaming. CrewAI 1.15.36 adds practical session and failure-observability improvements rather than another layer of autonomous orchestration. The winning agent architectures are increasingly the ones that make identity, waits, approvals, retries, and effects explicit enough to reject ambiguity.
