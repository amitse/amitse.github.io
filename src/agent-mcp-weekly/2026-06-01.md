## 🔌 MCP Protocol & Servers

**[MCP 2026-07-28 Release Candidate](https://github.com/modelcontextprotocol/modelcontextprotocol/releases/tag/2026-07-28-RC)** — Published 2026-05-29. The Model Context Protocol dropped its next revision as an RC, labelled `2026-07-28`. The specification is available in draft form at `modelcontextprotocol.io/specification/draft`. The release note is explicit about stability caveats: "This specification is not final. Changes may be introduced between the RC and the final release. SDKs will adopt this version at their own pace." The prior `2025-11-25` stable spec remains the production baseline. For the full delta, the changelog is linked from the release page — worth reading if you're implementing or maintaining an MCP server, since version negotiation behavior is documented under lifecycle. *(Source: MCP Specification GitHub)*

**LangGraph 1.2.4 — Server factory path integration tests added** — Released 2026-06-02 on [GitHub](https://github.com/langchain-ai/langgraph/releases/tag/1.2.4). The substantive change here is a backward-compatibility fix: `_on_started` callbacks from before the `cause` parameter was introduced now continue to work without breaking. Also notable is a new integration test for the "factory-graph" server path — which is the deployment pattern where LangGraph is used as a remote graph server rather than a local library. If you're building multi-agent systems using the LangGraph server SDK, this points to stability investment in the hosted execution path. Version 1.2.3 (2026-06-01) also landed, adding `RemoteGraph.interleave` support for SDK interleave projections — a streaming UX improvement for async agent workflows.

**Claude Code v2.1.161 — OTEL metrics and parallel tool call fixes** — Released 2026-06-02. This release adds two important operator-facing features: OTEL_RESOURCE_ATTRIBUTES values are now included as labels on metric datapoints, letting platform teams slice Claude Code usage by team, repo, or custom dimension. Parallel tool call behavior is also fixed: a failed Bash command no longer cancels other concurrent tool calls in the same batch. That second fix matters architecturally — if your agent fans out multiple tool calls and one fails, you want partial results, not a full rollback. The `/mcp` view also now collapses never-signed-in claude.ai connectors. *(Source: github.com/anthropics/claude-code/releases)*

**Claude Code v2.1.160 — Safety prompts before shell startup file writes** — Released 2026-06-02. Claude Code now prompts before writing to shell startup files (`.zshenv`, `.zlogin`, `.bash_login`) and git config, closing an unintended command-execution vector. `acceptEdits` mode also now requires confirmation before writing build-tool config files: `.npmrc`, `.yarnrc*`, `bunfig.toml`, `.bazelrc`, `.pre-commit-config.yaml`, `.devcontainer/`. This is a meaningful safety hardening: an agent that silently rewrites your `.npmrc` could intercept package installs. *(Source: github.com/anthropics/claude-code/releases)*

**Claude Code v2.1.158 — Auto mode on Bedrock, Vertex, and Foundry** — Released 2026-05-30. Auto mode (which lets Claude dynamically select thinking effort) is now available on Bedrock, Vertex, and Microsoft Foundry for Opus 4.7 and 4.8. Opt in via `CLAUDE_CODE_ENABLE_AUTO_MODE=1`. For enterprise teams routing Claude Code through their own cloud billing, this brings the efficiency benefit of auto-mode without requiring Anthropic direct API access. *(Source: github.com/anthropics/claude-code/releases)*

## 🏗️ Agentic Patterns & Architectures

**[How Anthropic Contains Claude Across Products](https://simonwillison.net/2026/May/30/how-we-contain-claude/)** — Published 2026-05-30 (Anthropic engineering post, surfaced by Simon Willison). This is rare: a detailed technical writeup of how agent sandboxing actually works in production. The stack: Claude.ai uses gVisor. Claude Code (local) uses Seatbelt on macOS and Bubblewrap on Linux. Claude Cowork runs a full VM. The design principle Simon quotes: *"We constrain where and how an agent can act with process sandboxes, VMs, filesystem boundaries, and egress controls. The goal is to set a hard boundary on what an agent can reach. For example, if credentials never enter the sandbox, they can't be exfiltrated."* The post also covers one risk Anthropic missed: the `api.anthropic.com/v1/files` exfiltration vector. This kind of retrospective transparency is unusually valuable for anyone building agent infrastructure. *(Source: simonwillison.net, 2026-05-30)*

**Simon Willison: Anthropic and OpenAI have found product-market fit** — Published 2026-05-27. Worth reading as context for why agent infrastructure is getting serious investment right now. Simon's data point: running Claude Code and OpenAI Codex as a "moderately heavy user" would have cost ~$2,180 at API prices over 30 days. He's paying $200/month on fixed plans. The implication: *enterprise customers are not getting those flat-rate plans* — they're paying API rates, and they're finding out their bills are large. "I had assumed that companies making extensive use of agents were getting similar discounts. It turns out I could not have been more wrong." This explains why model providers are competing aggressively on efficiency (MAI-Code-1-Flash, Claude Code Auto mode) — enterprise margins are real. *(Source: [simonwillison.net](https://simonwillison.net/2026/May/27/product-market-fit/))*

**datasette-agent-micropython 0.1a0 — MicroPython in WASM as an agent code sandbox** — Published 2026-06-02. Simon Willison shipped this alpha as the execution backend for [Datasette Agent](https://agent.datasette.io). The design: agents generate Python code, it runs inside MicroPython compiled to WASM — no native execution, no file system access, no network. Simon notes: "GPT-5.5 has so far failed to break out of the sandbox." The architectural bet is that WASM-sandboxed Python is tight enough to be safe for untrusted agent-generated code. This is a pattern worth watching: instead of OS-level sandboxing (gVisor, Seatbelt), small-scope agents can use language-runtime sandboxing that's cheaper to deploy. *(Source: [simonwillison.net](https://simonwillison.net/2026/Jun/2/datasette-agent-micropython/))*

## 💡 One Thing to Try

**Read Anthropic's agent sandbox architecture post and map it to your own setup.** Go to [simonwillison.net/2026/May/30/how-we-contain-claude/](https://simonwillison.net/2026/May/30/how-we-contain-claude/) for Simon's summary with the key quotes, then follow to the Anthropic engineering post. For each sandbox technique Anthropic describes (gVisor, Seatbelt, Bubblewrap, full VM, filesystem boundaries, credential exclusion), ask: does your agent deployment have an equivalent? Most teams running agents in production have thought about prompt injection but not about what happens if the model finds a "creative path" to exfiltrate via a files API. The `api.anthropic.com/v1/files` vector they mention — where an agent could upload files to Anthropic's infrastructure from inside a sandbox — is the kind of thing that only appears in detailed post-mortems. Anthropic is sharing theirs proactively.
