### MCP Has a Serious Security Problem
**[Source →](https://www.theregister.com/2025/04/21/model_context_protocol_security/)**

The Register covered a growing concern in the security community: because MCP servers can return arbitrary text that gets injected into an LLM's context, malicious or compromised servers can mount prompt-injection attacks against the AI agent calling them. The problem is structural — the protocol doesn't distinguish between data and instructions. Researchers argue the industry moved too fast to adopt MCP before threat models were properly worked out.

**Why it matters:** Any developer shipping MCP integrations to end-users needs to audit what content their servers return and consider output-sanitization layers before the wider community converges on a mitigation standard.

## Deep Dive: Remote MCP — What Changes for Developers

Until recently, MCP servers had to run as local processes on the same machine as the MCP client (or be tunneled via ngrok-style tools). Anthropic's remote MCP support in the API changes this fundamentally.

**Before:** MCP server → local stdio/socket → Claude Desktop (or local API client)  
**After:** MCP server → HTTPS endpoint → Anthropic API → Claude

This unlocks several architectural patterns that weren't previously practical:

1. **Shared organizational tools**: A single MCP server instance (e.g., "our internal Jira tools") can serve every Claude-using employee without each person running a local process.

2. **Serverless MCP**: Deploy a MCP server as a Cloudflare Worker, AWS Lambda, or similar — scale to zero, pay per invocation.

3. **Third-party MCP SaaS**: Companies can now publish hosted MCP endpoints as a product, similar to how Zapier/Make publish API integrations. Expect this category to explode.

4. **Auth complexity increases**: Remote servers need proper OAuth/API-key auth since they're now internet-accessible. The MCP spec has auth primitives but implementation quality varies widely across the ecosystem — audit carefully.

5. **Latency profile changes**: Remote network round-trips per tool call add up in multi-step agent workflows. Design tool interfaces to be coarse-grained (batch operations) rather than fine-grained to minimize round-trips.

The main implication for developers: if you've been deferring MCP adoption because local-only deployment was too constraining, that constraint is now lifted.
