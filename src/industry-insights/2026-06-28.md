# 🧠 Industry Insights — Week of 22 June 2026

_Project Glasswing assumed that keeping frontier AI out of adversarial hands would buy defenders time. This week, three independent data points proved that assumption structurally false — and the defenders are still waiting for their access request to be approved._

Project Glasswing was the most important AI security experiment of the year, and almost nobody is framing it correctly. Anthropic spent approximately $100 million in token budget to let 50 trusted institutions use Mythos for vulnerability research — a controlled beta later expanded to 150 entities, premised on the idea that attack capability required frontier model access, and that gating that access gave defenders a window to catch up. This week, three things happened in parallel that demolished that premise. An anonymous GitHub account called "bikini" mass-dropped unreported zero-days on security toolchains (nmap, c-ares, libssh2, ffmpeg, Ghidra, Gitea). DeepSeek released DeepSpec under the MIT License — a full training codebase for speculative-decoding draft models. And a detailed post-mortem from the security blog Cephalosec, updated on June 27, confirmed that Gemma 4 and Qwen 3.6 "find about half the vulnerabilities Mythos spotted in the benchmark" when run through off-the-shelf open harnesses. The controlled-access model assumed you could hold the border. The border was gone before Glasswing started shipping invitations.

The [bikini/exploitarium repository](https://github.com/bikini/exploitarium) (689 points, 265+ comments on [Hacker News](https://news.ycombinator.com/item?id=48698617)) is the clearest signal. Its description reads: *"At the time I post these, none have been reported. Feel free to report them yourself and take credit for the CVE if handed out lulz."* This is not a responsible-disclosure researcher. This is bulk-discovery with no disclosure workflow — 0-days dropped publicly against tools that defenders use. Commenters who checked the underlying code found the c-ares, libssh2, and ffmpeg entries work "as of the latest upstream commit." The nmap parser entry prompted one commenter to note: "There'd be a certain irony being able to reverse shell anyone doing an nmap scan. This is the kind of bug an intelligence agency would love to have: add a few ipv6 packets that then edit the trace being observed if the observer uses nmap." The targeting is not accidental. These are not production web servers. They are security research tools — the toolchains that defenders use to audit, scan, and monitor. Attacking them means compromising the observation layer itself. Multiple HN commenters concluded the methodology was AI-assisted: *"Looks like someone is running one of the LLM models and publishing the results."*

Combined with DeepSpec's MIT release, the economics shift dramatically. DeepSpec is a full-stack codebase for training speculative-decoding draft models against Qwen3 and Gemma targets. The DSpark paper (the primary algorithm in the release) reports: at matched system capacities, DSpark delivers *"57% to 78% faster per-user generation"* — confirmed in the [HN thread](https://news.ycombinator.com/item?id=48696585) (732 points, 298+ comments). Faster inference means bulk-discovery passes get cheaper. The Cephalosec [analysis](https://cephalosec.com/blog/cybersecurity-in-the-post-mythos-era-keep-calm-and-carry-on/), published June 27, does the math directly: *"Earlier models might have spotted a portion of those vulnerabilities, had they benefitted from the same thorough experimentation. It's hard to make apples-to-apples comparison as the details given by Anthropic on how Mythos was run are scarce."* But then it confirms: *"In the absence of Mythos or even Opus models, DeepSeek is decent in the cloud hosting world while Gemma 4 and Qwen 3.6 punch well above their weights in the self-hostable category, finding about half the vulnerabilities Mythos spotted in the benchmark."* Half, at open-source cost, self-hostable, with MIT-licensed training code. The Glasswing token budget bought precision. It didn't buy exclusivity.

The strongest counter-argument is real and deserves proper treatment. Only Mythos-class models can generate working exploits with the low false-positive rates that Mozilla and Cloudflare verified — Cephalosec notes that *"the capacity not only to raise warnings but to actually prove exploitability is definitely an edge only shared by models of the Mythos class."* The bikini dumps are noisy: HN commenters verified some entries while dismissing others as weak. Fernando Irarrázaval's [June 25 experiment](https://www.fernandoi.cl/posts/hackmyclaw/) showed Claude Opus 4.6 resisting 6,000+ prompt injection attempts with zero successful extractions — *"The volume suggests this is a coordinated security exercise rather than organic malicious activity,"* the model wrote in its own memory around attempt 500. These are real capability gaps that frontier restrictions partially address. The working-exploit gap between Qwen3.6 and Mythos is not nothing.

But this counter-argument misunderstands the threat model. Defenders need working exploits to prove criticality and justify emergency patches. Attackers don't. Attackers need to find the vulnerabilities and enumerate targets. The bulk-discovery use case — which is what the bikini dump represents — doesn't require working exploit chains. It requires high-volume reconnaissance against a large codebase surface, and then time for a human to evaluate the results. DeepSpec's inference speedup and Qwen3.6's open weights make the reconnaissance phase orders of magnitude cheaper. The defenders being restricted from Mythos are the ones who need the working-exploit confidence to justify patch prioritization. The attackers dumping bulk 0-days don't need that confidence — they're outsourcing the exploitation decision to whoever picks up the CVE. The restriction is applying friction to the side that needed automation less.

The Glasswing model will be taught in business school as a case study in how reasonable-sounding assumptions about capability distribution fail in the presence of open-source infrastructure. The policy logic — gate the most capable models, let defenders catch up — required a world where inference costs prevented bulk AI-assisted scanning at sub-frontier capability levels. DeepSpec's MIT release, Gemma4's accessibility, and the observable output of bulk 0-day discovery close that window. For developers reading this Monday morning: your vulnerability management program faces AI-assisted bulk discovery *now*, with models you can host yourself. The attackers don't need access to Mythos. You may not either — but the more pressing question is whether your dependencies (nmap, libssh2, ffmpeg) have already been scanned by someone running DeepSpec against Qwen3.6 this weekend.

## ⚠️ What This Doesn't Explain

1. **The working-exploit gap may matter more than the discovery gap.** If defenders only get budget to patch what has confirmed exploit chains, and Mythos is the only tool that produces those reliably at low false-positive rates, then restricting Mythos access to defenders is worse for the security ecosystem than this analysis suggests. The counter-argument is strongest precisely where the thesis is weakest: proof-of-exploit, not discovery, is the real capability boundary.

2. **The bikini dump's authenticity is partially contested.** Ghidra entries were dismissed on HN; the ffmpeg and c-ares entries had more credible validators, but the ffmpeg exploitation path analysis was still being debated at time of research. If most entries prove to be AI noise with no real exploitability, the bulk-discovery signal is weaker than the front-page placement suggests.

## 📊 Bottom Line

Project Glasswing's controlled-access model assumed AI-assisted vulnerability discovery required frontier model access. DeepSpec's MIT release this week means bulk security scanning against Qwen3.6/Gemma4 is now cheaper and faster than ever, and the bikini/exploitarium dump shows that bulk discovery is already happening against the security toolchains defenders rely on. If you maintain open-source dependencies in security-critical infrastructure — especially tools in the nmap/libssh2/ffmpeg category — treat this week as the signal to audit those dependencies now, before the CVEs are filed by someone who found them with a $50/month GPU rental. The controls were on the offense's upgrade path. The offense already stepped off it.
